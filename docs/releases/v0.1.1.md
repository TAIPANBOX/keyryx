# keyryx v0.1.1

A patch release on v0.1.0. The image is signed in the legacy `.sig` format that the cluster admission controller (policy-controller v0.15.1) reads, so the signature is verifiable there. Its reader takes only that tag, and before this release the image signature was not. cosign stays at v3.1.3, and the release workflow's `sign-blob` steps are unchanged. Nothing else changes in behaviour.

Tag: `v0.1.1`. Image: `ghcr.io/taipanbox/keyryx:v0.1.1`, `linux/amd64` and `linux/arm64`. There is no moving tag (no `latest`, no `main`).

## Changed since v0.1.0

- #9, `chore(deps): bump agent-stack-go to v2.0.0`. The shared wire-type import moves to the `/v2` module path. Nothing an operator sets or sees moves with it.
- #10, `ci(release): sign the image in the legacy format policy-controller reads`. The image sign step adds `--new-bundle-format=false --use-signing-config=false`.

No other commit lies between the v0.1.0 tag and this release.

## Upgrade

Nothing to change in a deployment. Pull `ghcr.io/taipanbox/keyryx:v0.1.1` in place of `v0.1.0`; the configuration and the stored state are the same.
