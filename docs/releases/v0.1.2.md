# keyryx v0.1.2

A patch release on v0.1.1. The witness now writes each trailryx attestation with mode 0640, in directories of mode 0750, so a reader in the witness's group can open it. Before this release the file was 0600, and `trailryx-node read --pack` could not open it from another account. Nothing else changes in behaviour: no key, no statement, no log and no route moves.

Tag: `v0.1.2`, released 2026-10-19 from `main` at `21edb5c`. The image is `ghcr.io/taipanbox/keyryx:v0.1.2`. There is no moving tag (no `latest`, no `main`).

## Changed since v0.1.1

- `internal/witness`: `attest` sets the attestation file to 0640, and its tenant directory and the attestations directory to 0750, explicitly rather than through the umask. A mode change that is refused fails the attestation, and no file is filed.
- `go.mod`: `agent-stack-go` moves from v2.0.0 to v2.0.1 (#12). That release changes no Go code, so nothing in this binary's behaviour moves with it.

## Upgrade: the attestation files

Attestations written by v0.1.1 keep mode 0600. The witness writes each root's attestation once and does not rewrite earlier ones. To let the record plane read the older files, run these as the witness's account, once:

    chmod 0750 <KEYRYX_WITNESS_DATA>/attestations <KEYRYX_WITNESS_DATA>/attestations/<tenant>
    chmod 0640 <KEYRYX_WITNESS_DATA>/attestations/<tenant>/<root>.json

The witness data directory stays 0700, which the witness requires to start. A reader that is another account must share the witness's group and be given the `attestations` directory itself, not the data directory. The deployment note in the README says the same.
